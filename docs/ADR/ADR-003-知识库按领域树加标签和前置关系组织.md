# ADR-003：知识库按“领域树 + 标签 + 前置关系”组织

- 日期：2026-10-27
- 状态：已采纳

## 背景
最初只有 CFG、LDM 两个专题，首页平铺，`tags` 的第一个词（“扩散模型”）实际上兼当领域。加入 Softmax 这种基础专题后，“扩散模型”已经不能概括全部内容；专题之间也开始互相依赖（CFG、LDM 都用到 softmax），平铺列表看不出该先读哪篇。

## 考虑的方案
1. 只规范标签，约定第一个标签是领域：改动最小，但专题一多就不好找，也表达不了依赖。
2. 领域树 + 标签：首页按领域分组，标签跨领域筛选；专题之间的关系只靠正文里的跨专题链接。
3. **领域树 + 标签 + 前置关系（采纳）**：在方案 2 的基础上，每个专题可以声明“建议先读”的专题，反向的“被哪些专题用到”自动算出。

## 决定
- 领域树写在 `src/topics/taxonomy.ts`，两级：领域 › 子领域。专题在 `meta.area` 里写 `领域id/子领域id`。首页按树的顺序分组，没有专题的子领域不显示。
- `meta.tags` 只放跨领域的关键词（如“注意力”“采样”），不再放领域名。首页可以按标签或领域筛选，筛选条件放在地址里（`#/?tag=…`、`#/?area=…`），专题页的面包屑和标签都能直接跳过去。
- `meta.prereqs` 列出建议先读的专题 slug；`usedBy(slug)` 反查。专题页头显示“建议先读”和“被这些专题用到”，首页卡片显示“建议先读”。
- 单元测试保证：每个 `area` 都在树里，`prereqs` 指向存在的专题、不指向自己、没有环。
- Softmax 放在“机器学习基础 › 概率输出与损失”，CFG、LDM 放在“生成模型 › 扩散模型”；CFG 前置 Softmax，LDM 前置 CFG 和 Softmax。

## 后果
- 新专题必须选一个已有的子领域，或者先在 `taxonomy.ts` 里加一个。领域和子领域的 id 会出现在筛选链接里，发布后不要改名。
- 前置关系是人工维护的，只写“读这篇之前最好先懂”的专题，不是所有出现过的跨专题链接都要写成前置。
- 首页卡片的可访问名称里包含“建议先读”的专题名，测试里定位卡片要按标题（heading）找，不要按链接文字的正则找。
